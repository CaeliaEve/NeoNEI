# 自适应加载与缓存恢复

用户已批准上一轮建议中的首批性能与可靠性优化。本轮沿用现有工作区和已验收 Catalog，不重新导出游戏数据，不调整布局与像素采样。

## 方案

固定相邻页预取在快速滚动时不足；无限预热会挤占当前点击和有限纹理内存。采用有上限的方向预取：根据相邻请求的方向、距离与时间准备前方 1–4 页，反向、搜索或数据集切换取消旧任务；每轮最多加载四张原生图集，当前页永不等待预热。

配方预热走与点击相同的数据请求和缓存，低优先级、可取消，只准备第一条实际配方的首帧。原生帧映射存在时复用浏览图集。切换目标取消旧预取，点击可共享正在进行的读取，完整配方目录与候选不截断。保持现有 192 MiB 共享解码预算。

应用启动时监听新版 ServiceWorker 的 installed 状态，仅在 build 与当前文档一致且全部文件校验通过时接管；不强制刷新，不删除仍在使用的旧版本。安装期间保护原活动版本，失败后保留其离线能力。资源缓存读取发现损坏时只联网补取目标文件，验证后替换；离线损坏继续如实报错，禁止无限重试。

## 验证

用现有 Node 测试覆盖方向反转、请求取消、共享读取、首帧优先与坏缓存恢复，以及新旧文档交接条件。构建、类型检查后，在独立本地候选服务测试连续滚动、首次配方和跨版本离线刷新。记录真实耗时与样本条件，不将暖缓存测试称为冷启动。保留旧包用于回退，再更新 3002 本地启动配置。
